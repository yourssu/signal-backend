# Issue 생성

Git 공유 파일을 변경하기 전에 사용한다. 한 Issue에는 한 주제만 담고 짧고 쉽게 쓴다.

## 제목

`type: 한글 평서문` 형식을 사용한다. 파일명보다 사용자에게 달라지는 동작을 쓴다.

## 본문

중간 규모 이상은 다음 구조를 사용한다.

```markdown
## 영향 범위
- `경로`: 한 줄 설명

## 구현 내용
### AS-IS
- 증상 → 원인

### TO-BE
- [ ] 구체적인 완료 동작

## 특이사항
```

`## 특이사항`은 사용자가 직접 작성한다. 에이전트는 제목 아래에 문장, 불릿, 공백용 `-`를 넣지 않고 항상 비워둔다.

작은 버그는 `문제 → 원인 → 해결` 자유 형식을 사용할 수 있지만 마지막 `## 특이사항`은 동일하게 비운다.

## 절차

1. 초안을 사용자에게 보여주고 확인받는다.
2. `gh issue list`와 관련 PR로 중복·부분 해결 여부를 확인한다.
3. 승인된 초안을 `gh issue create --repo yourssu/signal-backend`로 등록한다.
4. URL을 보고하고 해당 Issue 번호를 이후 스펙·브랜치·PR에 연결한다.
