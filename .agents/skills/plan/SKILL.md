# 계획

1. 추측하지 말고 관련 코드, 테스트, 설정, Git 이력을 읽는다.
2. 요구사항별 변경 지점과 기존 패턴을 연결한다.
3. 데이터·API·배포 호환성과 회귀 가능성을 기록한다.
4. 테스트를 구현보다 앞에 배치하고 실제 검증 명령을 명시한다.
5. 독립 작업만 병렬 wave로 나누고 파일 소유권과 의존성을 적는다.

Medium은 `plan.md`, Large는 `plan.md`와 `tasks.md`를 작성한다. 사용자의 선택이 결과를 크게 바꾸면 계획 승인 전에 한 번에 하나씩 질문한다.
